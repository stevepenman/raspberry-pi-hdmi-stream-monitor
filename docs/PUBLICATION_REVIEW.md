# Publication review

## Scope and preparation

This is an isolated portfolio copy. Source allowlisting retained the two Python entry points and the browser player with its existing third-party notice. The dependency file and configuration example were rewritten; documentation, tests, CI and demonstration imagery were created for this edition. Existing version-control history was not copied.

Excluded categories include account files and credential documents, generated operational guides, document conversion utilities, cached bytecode, logs, recordings, data exports, reports, databases and any existing project licence. No original user mapping, password hash or operational sample data is included. The demonstration image was generated by `SyntheticCamera`; it contains no captured workplace imagery.

Names and identifiers in the copied source, filenames, configuration, comments and documentation were reviewed. The application branding was replaced with a generic descriptive name. Targeted local checks for the supplied organization, equipment and internal-project references found no matches in the publication candidates. The reference strings themselves are deliberately not recorded here or in the public scanner.

The default configuration is synthetic MJPEG bound to loopback. The demo does not open capture devices, launch an encoder/player, send email or call external services. The browser's external player fallback was removed. Equipment capture and receiver requests require explicit opt-in. Runtime credentials, logs, media and local configuration are ignored by Git.

## Final inspection

The reviewed publication set is restricted by an explicit allowlist in `tools/check_publication.py`. It scans tracked and nonignored untracked files for common credential formats, password hashes, private keys, certificates, email addresses, private IPv4 addresses, credential-bearing URLs and personal directory paths. Unexpected files are rejected. Separate local searches checked the requested identifiers and remaining organization/network references without adding those search terms to public files.

The synthetic PNG was visually inspected. The bundled third-party JavaScript was also scanned, and its SHA-256 matched the pinned upstream distribution. Its upstream attribution is intentionally retained; those notices identify the dependency authors, not a workplace relationship.

The scan examines the working files selected by Git, not old commits or arbitrary staged blob versions. This fresh repository has no imported history. A scan pass is a limited hygiene check: it cannot reliably identify every secret, custom internal name, image metadata field, confidential algorithm or ownership issue. Re-run it and inspect the staged diff after any changes.

## Required personal review before upload

1. Confirm you are authorized to publish the source and any work created in an employment or contractual context. Removing names does not establish permission or ownership. Resolve uncertainty with the appropriate rights holder before making the repository public.
2. Confirm the source logic and architecture can be disclosed, beyond the identifiers and data already removed. Review both Python files and the final staged diff.
3. Check the CV contribution wording against your actual role and any assistance or third-party work. No performance, savings or deployment claims are supplied.
4. Review the retained third-party component and its notices. This preparation did not perform a dependency vulnerability audit.
5. Choose Git commit author details intentionally. Git records the name and email you configure; use your GitHub-provided no-reply address if desired. No commit was made on your behalf.

No project licence or ownership claim has been added. No repository was published or pushed, and no remote was configured. The local virtual environment is for verification only and is excluded from upload.
